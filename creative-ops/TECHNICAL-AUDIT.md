# Creative Ops — технический аудит

## Итог

Основной workflow Creative Ops проверен в браузере от создания задачи до повторной сдачи и приёмки. Данные, комментарии, AI-расходы, результаты и история сохранялись в локальной PostgreSQL. TypeScript, lint, unit/integration tests, Prisma validation, production build и аудит npm-зависимостей прошли.

**Статус:** готово для локального тестирования, но не для production-деплоя без настройки private Vercel Blob и проверки production-переменных/хранилища. Основной workflow проверен вручную, но полная ручная приёмка всех действий и production deployment не выполнялись.

## Архитектура

- Next.js App Router, React, TypeScript и Tailwind CSS.
- PostgreSQL + Prisma; локальная база и отдельная база для интеграционных тестов.
- NextAuth Credentials с JWT-сессиями; роли BUYER, CREATIVE и MANAGER проверяются на сервере.
- Route handlers отвечают за HTTP и валидацию; `src/server/services` содержит бизнес-операции и транзакции.
- Kanban использует `@dnd-kit`; аналитика — Recharts; файлы предназначены для private Vercel Blob.

Next.js обновлён с 14 до 15.5.29, Vitest — до 5.1.0, а minimatch для TypeScript ESLint зафиксирован безопасным override. Обновления выполнены для устранения выявленных advisories; App Router и остальная архитектура сохранены. **Отклонение от ТЗ:** в запросе указан Next.js 14, а текущая сборка использует 15; если строго требуется 14, до production следует проверить и применить безопасную версию 14 вместо текущей.

### Исправленные проблемы

- Закрыт найденный security issue MEDIUM: production больше не принимает демо-аккаунты, а демо-кнопки не показываются в production.
- Исправлены TypeScript/ESLint ошибки и HTTP-ответы для конфликтов workflow и нарушений бизнес-правил.
- Доступ к private-вложениям проходит через endpoint с авторизацией; миграция добавляет nullable `storagePath` без потери существующих данных.
- Во время бета-проверки исправлена форма создания задачи: ссылки на загружаемые референсы больше не публикуются, файл сохраняется в private storage и читается через проверку доступа к задаче.
- Полный npm audit обнаружил уязвимости Vitest/tinypool и minimatch в dev-инструментах. Зависимости обновлены, финальный `npm audit` сообщает 0 vulnerabilities.

## Проверки

- `npm run typecheck` — успешно.
- `npm run lint` — успешно, без предупреждений ESLint.
- `npm run test:unit` — 15 passed; интеграционная suite пропускается в обычном запуске намеренно.
- `npm run test:integration` — 2 passed на локальной PostgreSQL test DB.
- Браузерный сценарий: вход всех трёх ролей, создание задачи, смена статусов, ссылки, комментарии, AI-расход, результат в двух раундах, возврат, приёмка, история и аналитика.
- Проверка ролевых отказов: BUYER получает `403` на аналитику, MANAGER — `403` на изменение статуса, запрос без сессии — `401`.
- Покрытие строк unit-набора — 24.27%; основная бизнес-логика `task.service.ts` покрыта слабо (~0.82%), поэтому нужны дополнительные API/E2E тесты.
- `npm run db:validate` — успешно.
- `prisma migrate status` — схема основной локальной БД актуальна.
- `npm run build` повторно прошёл после исправления private Blob upload.
- `npm audit` — 0 vulnerabilities.
- Повторная генерация Prisma Client завершается Windows `EPERM` при замене query-engine DLL; ранее созданный client успешно используется сборкой. Не останавливать неизвестные процессы ради этой операции; повторить её после выяснения владельца блокировки DLL.

## Локальный запуск

- Приложение: <http://localhost:3000> (порт тестового dev-сервера мог сместиться на `3001`, если `3000` занят).
- PostgreSQL: `127.0.0.1:55432`
- Для входа используй одну из демо-кнопок на локальной странице входа. Пароли хранятся только в локальном `.env` и в этот отчёт не включены.
- Для остановки dev-сервера останови процесс, запущенный командой `npm run dev`; PostgreSQL локально работает отдельным процессом.

Подробные команды и актуальный статус ограничений см. в [README.md](./README.md).
